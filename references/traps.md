# Trap catalogue

The expensive mistakes from a shipped mobile puzzle game and its two predecessors, generalised.
Each entry gives the mechanism (the general truth), the incident that taught it, and the fix plus
the check that keeps it fixed. Scan the groups a piece of work touches before you start it.

**Read when:** before planning or starting a slice, before a review or fixer pass (as a hunting
list), and whenever something passes every test but looks or behaves wrong.

## How to use it

1. **Before a slice,** copy the relevant numbers into its brief as "known traps": a visual slice
   scans groups 5–8, a money slice 4, 9, 10 and 14, a release slice 12–13, kickoff and agent work
   1–2, any test, guard or script 3 and 15. A re-hit trap is a review finding, cited by number.
2. **At kickoff or adoption,** seed the builder skill's "Inherited" heading with the entries that
   fit the stack and domain (`references/project-kit.md` §5). Do not edit this file per project.
3. **New traps go in the project's log** in the session that hit them, under a dated heading, in
   the builder skill's entry format, never this file's T-n shape. Convert what you copy from here
   the same way, with "Here:" and ending "(catalogue T-n)"; an inherited entry may be one line
   (format: `references/project-kit.md` §5). Mark a repeat "(again)"; never delete either entry.
4. **Promote a trap the second time it bites** into a lint, a test rule, a script or setup check, or
   a template line: three logged traps recurred in the source (`references/project-kit.md` §5).
5. **Tags:** untagged entries are stack-neutral; `[Flutter]`, `[iOS]`, `[Android]`, `[shader]`, `[shell]`
   mark the few kept here. Stack traps: `references/stack-flutter.md`, `references/stack-other.md`.

This file's shape: **T-n. Mechanism.** *Seen:* the incident. *Fix/guard:* the fix, and the check
that holds it. Numbers never change; a later entry takes a letter at its group's end (T-17a).

> **Dated facts (as of 2026-10 — re-verify before relying):** every *Seen:* line is a 2026
> observation. Re-verify any entry that names OS, store, SDK, renderer, test-runner or tool behaviour
> against the installed source or the official docs. The untagged mechanisms and fixes are durable.

## The fifteen most expensive

Read these even when short of time: T-1 (green suite, plain visuals) · T-10 (upload framed as the
default) · T-18 (a guard never seen to fail) · T-36 (startup throws before the first frame) · T-39
and T-40 (idealised fakes) · T-46 (translucent cues) · T-64 (double exposure) · T-91 (overwriting a
save) · T-96 (counters merged by value) · T-102 (timeout to the unsafe side) · T-109 (content valid
but bad) · T-116 (scaffolder over the repo) · T-125 (built is not runs) · T-130 (claims not from
code) · T-136 (an ad or purchase recorded after the await).

## 1. Process and docs

Depth: `references/project-kit.md`, `references/planning-and-slices.md`, `references/orchestration.md`.

- **T-1. A green suite under plain visuals is a failed product.** *Seen:* a predecessor game was
  judged "it looks like an app, not a game" across three builds with hundreds of green tests.
  *Fix/guard:* the owner's real criterion heads the builder skill; done requires renders and device
  screenshots looked at; the owner never sees below-bar work (T-12).
- **T-2. A handoff's "green" is a claim.** *Seen:* the progress doc said green over a red tree twice;
  one "red" was only a copy without `.git` failing git-based tooling tests.
  *Fix/guard:* run the baseline yourself on arrival; red means fixing it is the task; decide in the
  real tree whether code or environment is red.
- **T-3. A stale doc is obeyed, and an unchecked rule is not known.** *Seen:* the builder skill kept
  "refuse input during animation" after a decision reversed it; a layer rule overclaimed until a
  guard ran. *Fix/guard:* the changing slice updates the docs; reviewers ask "do the docs say only
  true things?"; every house rule names its guard.
- **T-4. Two copies of one fact drift.** *Seen:* a beat map copied into the sound generator said
  600–1300 ms while the app said 450–1350 ms; two progress classes disagreed after a skip.
  *Fix/guard:* one source, read by the other (a test imports the generator's constants or parses the
  doc table); a doc that a test parses says so, because its format is now an API.
- **T-5. Plans, reasons and research written before measurement go wrong.** *Seen:* a plan required
  profiling on a debug-only simulator; "no daily mode: needs a pipeline" was false; research proposed
  a first ad at level 8 against a house rule. *Fix/guard:* "as built" entries; a reason proven false
  is new information, so supersede it with a dated entry; research feeds decisions, never replaces them.
- **T-6. Parallel lanes each bump the same persisted schema.** *Seen:* two lanes raised the save
  version independently; stub assertions went red at integration. *Fix/guard:* the integrator ships
  one latest version reading every older one; invert "still a stub" tests into "no part is a stub".
- **T-7. Status labels and notices go stale.** *Seen:* a "stopped" notice for long-committed work;
  "not committed" labels on finished entries. *Fix/guard:* re-derive state from `git log` and
  `git status` before reporting; replace labels with commit hashes.
- **T-8. An optional review gets skipped, and its defects ship.** *Seen:* nine fixer passes found about
  74 real defects after each slice's own tests were green. *Fix/guard:* review then fixer pass are
  fixed steps of done; reviewers re-run and re-render instead of trusting the builder's report; solo,
  review the diff as a separate pass against the relevant trap groups.
- **T-9. Interrupted work is redone, or relaunched without its predecessor's output.** *Seen:* a
  relaunch passed a placeholder instead of the previous lane's report; research lived only in one
  session's scratch folder. *Fix/guard:* save reports to files and pass paths; a finisher continues
  from `git status`; archive research into `docs/<slug>/research/`.

## 2. Owner and permissions

Depth: `references/working-with-the-owner.md`.

- **T-10. Framing the irreversible step as the default next step.** *Seen:* "once the icon is ready,
  I'll build and upload" had to be corrected: no upload until the owner tested on a device and
  approved. *Fix/guard:* write it as "when you approve: …"; test builds go by a non-public route (cable
  or dev install, local package, simulator recording); any upload, test tracks included, only on the
  owner's request for that specific upload; end milestones with, word for word: "Nothing is uploaded
  unless you ask for that specific upload, and nothing goes to review or the public before you have
  tested it on your device and approved."
- **T-11. Asking a non-expert owner design questions offloads work and gets worse answers.** *Seen:*
  genre-settled questions went to an owner who had said they had no design experience.
  *Fix/guard:* ask only what is theirs (money, accounts, legal identity, keys, device feel, scope,
  release), batched, in their language, each with a recommendation; a developer-owner wants options.
- **T-12. Anything the owner sees is judged as the product.** *Seen:* a default icon and a white
  launch flash would have read as unfinished on the first device build. *Fix/guard:* keep a list of
  programmer-art tells (default icon, launch flash, system fonts, unstyled dialogs, placeholder text)
  and clear it before any build the owner touches.
- **T-13. A model cannot perceive some qualities.** *Seen:* the owner feared weak sound; a listening
  page with each cue in context, Good/Weak buttons and notes let them judge it "suitable", so nothing
  was bought. *Fix/guard:* state the limit, build the smallest tool that records the owner's verdicts
  where you can read them, research a costed fallback, ask before buying, re-judge on a device.
- **T-14. Real services keep traces of your tests.** *Seen:* debug-signed release test builds uploaded
  mapping and symbol files to the owner's crash project; a test save reached their cloud account.
  *Fix/guard:* gate release-only uploads on the real signing key and archive builds (prove it with a
  dry run), strip production config from probes, disclose every trace.
- **T-15. Accounts, logins, downloads and purchases are the owner's.** *Seen:* free recordings sat
  behind a login. *Fix/guard:* the owner fetches login-gated files from a table you give them (purpose,
  file, link, size, licence); show name, source and size before any download; get a yes before any
  purchase.
- **T-16. Editing a dependency the owner maintains, or committing someone else's art.** *Seen:* the
  owner's own ad wrapper lacked eight needed things; competitor screenshots helped side-by-side
  judging. *Fix/guard:* a one-file workaround behind a guarded import exception plus an upstream
  request with file:line evidence; competitor material stays in scratch.
- **T-17. Agents that commit, upload or act outside their lane bypass verification.** *Seen:* after the
  lanes' own suites were green, slice reviews still found 4–27 real defects each. *Fix/guard:* only the
  lead commits, after re-running the suite and looking; every agent prompt says "no commit, upload,
  store, console or memory note".
- **T-17a. Changing repo state while a workflow tests the opposite state.** *Seen:* real backend config
  arrived while a workflow tested the "no config" path; selftests had broken once when config landed
  (T-29). *Fix/guard:* hold the change until the run ends; tests accept either state.
- **T-17b. Research workers without the owner's answers guess them.** *Seen:* readers who could not see
  who makes the signing key or tests on a device guessed; the brief voided two of their items.
  *Fix/guard:* every brief carries the owner's answers verbatim and dated, open ones marked ASSUMED.
- **T-17c. A gate on reversible work stalls the project and protects nothing.** *Seen:* the owner
  relaxed the plan's "nothing in Phase 3 before a yes" to "no upload before approval". *Fix/guard:*
  Gate 0 holds only the public or permanent; ids stay provisional (`references/kickoff.md` §10).
- **T-17d. A blocked account change left half-applied.** *Seen:* the permission system stopped an
  analytics ads-personalisation change mid-edit. *Fix/guard:* close the editor unapplied; hand the
  owner the exact click path.
- **T-17e. A recommendation standing in for an unanswered question becomes a silent decision.**
  *Seen:* a trial's owner could not be reached and the method had no convention; the builder
  invented ASSUMED tags mid-kickoff. *Fix/guard:* ASSUMED entries, listed in PROGRESS; nothing
  permanent (ids, store records, vendors, published text) rests on one; Gate 0 confirms them.
- **T-17f. Owner facts kept in another project's memory are misfiled or unreachable.** *Seen:* a
  trial ran from another project's directory, so its session memory was that project's. *Fix/guard:*
  PROGRESS "Standing owner preferences" always; memory notes only in this project's own memory.

## 3. Verification and tests

Depth: `references/verification.md`, which tells most of these incidents in full. About a third of
all logged traps were tests that passed while the thing they guarded was broken.

- **T-18. A guard not seen to fail is not a guard.** *Seen:* a "≥ 3:1 line across every wall" pixel
  guard was met by the gutter between tiles and passed with every wall deleted.
  *Fix/guard:* remove the feature (a test-only switch or a mutation in a copy), watch it go red, keep
  the control in the test file; when a guard fails, decide which side is wrong, never loosen it to pass.
- **T-19. A negative control must fail for its own reason.** *Seen:* a fixture failing on a typo
  counted as "expected". *Fix/guard:* assert each case's failure text.
- **T-20. Two guards on one claim make each negative control lie.** *Seen:* deleting route dedup passed
  because puzzle dedup caught the same duplicates. *Fix/guard:* neutralise the other guard.
- **T-21. An expectation derived from today's code cannot fail.** *Seen:* `expect(scale, Press.scale)`.
  *Fix/guard:* the spec's literal (`0.96`) or the parsed doc; `current + 1` for versions.
- **T-22. A guard on a model does not guard the output.** *Seen:* a gait model proved feet never slide
  while the painted feet slid. *Fix/guard:* assert on painted geometry, pixels or the shipped artefact.
- **T-23. A guard over shipped data may never reach its branch.** *Seen:* a card-shrink loop was wrong
  only on phones no shipped board reached. *Fix/guard:* a synthetic input, seen failing.
- **T-24. A compound condition needs one scenario per term.** *Seen:* every offer test began with the
  reveal idle, so `|| reveal.isRunning` could be deleted green. *Fix/guard:* one test per term.
- **T-25. A guard over three previews misses the fourth.** *Seen:* a share card's completion badge
  covered the mascot on 10 levels and 99 dailies. *Fix/guard:* loop over every item × theme × size ×
  pose × text scale.
- **T-26. Regex guards over source are wrong both ways; a blind scanner stays green.** *Seen:* a
  comment satisfied an import ban once, and a doc comment tripped it later. *Fix/guard:* tokenise;
  must-catch, must-ignore and "it saw real input" checks.
- **T-27. A broken mutation copy reads as "survived".** *Seen:* a copy missing the package graph
  errored on every run. *Fix/guard:* prove the copy green unmutated; only assertion failures kill;
  never mutate the shared tree.
- **T-28. A mutation the test never executes, or a fallback absorbs, proves nothing.** *Seen:* a theme
  deleted from a puzzle was still found through the level id. *Fix/guard:* mutate the output.
- **T-29. Tool selftests lie by omission.** *Seen:* deleting a case kept CI green; a case passed
  because an earlier step failed first. *Fix/guard:* assert each case by name; match FAIL text on
  stderr; accept either repo state.
- **T-30. A removed timeout fails slowly and confusingly.** *Seen:* a deleted bound gave a 30 s harness
  timeout. *Fix/guard:* a short injected bound inside a test-level timeout that calls `fail`.
- **T-31. Byte-exact pins break on upgrades and hide in unexpected folders.** *Seen:* a theme hash pin
  sat outside the render-test folder. *Fix/guard:* list every pin; hash before claiming "unchanged".
- **T-32. Easy cases hide structural bugs.** *Seen:* square-only boards hid a wrong stride; averages
  hid a "big" level no harder than a regular one. *Fix/guard:* a non-square case; compare per item.
- **T-33. A test measures something next to the claim.** *Seen:* a 0.6 × width tolerance let an object
  hang 73 pt off a 430 pt phone. *Fix/guard:* measure the named property in its own units and real
  parent.
- **T-34. A check that cannot fail where it matters.** *Seen:* render tests wrapped in try/catch; rule
  legality guarded only by debug asserts, which vanish in release. *Fix/guard:* no try/catch in tests;
  what must hold in release is enforced by shipped code or a test.
- **T-35. Some bugs need many items in one process.** *Seen:* a bounded cache disposed an entry a
  widget still held, at level 30 of a 200-level run. *Fix/guard:* a continuous run of the whole
  content by simulated finger on the real screens (~60 s for 200 levels); caches hand out copies.
- **T-36. Startup code that throws before the first frame passes every widget test.** *Seen:* a
  `Future<void>` that was really a `Future<List>` threw at `.timeout()` in the entry function [Flutter],
  leaving the app on its launch screen. *Fix/guard:* cold-launch every integrated build and read the
  device log; test that a throwing or hanging init still reaches the first frame.
- **T-37. A pixel guard must measure the feature where only it changes.** *Seen:* a whole-strip diff
  diluted a 0.45% mark. *Fix/guard:* diff against the render without the feature, cropped; mean and
  changed-pixel count.
- **T-38. A detector must match the defect's signature, measured first.** *Seen:* a guess put the
  mascot 0.85 cell tall where pixels said 0.37. *Fix/guard:* measure the largest variant; detect the
  defect's own shape.
- **T-38a. A "nothing left" check that knows one marker form, or matches itself, reports done.**
  *Seen:* a scaffolder wrote `TODO(NAME)`, its templates `[TODO: …]`; each suggested grep caught one
  form, so a still-template kit looked filled. *Fix/guard:* one marker grammar; one check for every
  form that never matches itself (`scripts/init_kit.py --check`).
- **T-38b. A determinism test that shuffles one input misses the order that differs.** *Seen:* a
  trial's money probe shuffled expense order and passed with the id tie-break removed; phones differ
  in member key order inside one split. *Fix/guard:* permute every input whose order can differ
  between devices; see it fail with the tie-break removed (`references/domain-apps.md` §6).

## 4. Fakes and seams

Depth: `references/verification.md` §5, `references/architecture.md` §1.

- **T-39. A fake that answers at once proves no timeout.** *Seen:* six bounds on store calls could be
  deleted with every test green. *Fix/guard:* the fake holds every bounded call; assert the operation
  ends within its bound while the hold is never released.
- **T-40. A fake without the real timing and state changes hides the windows that matter.** *Seen:* a
  fake ad showed synchronously while the real service first awaited a mute for up to 2 s; a fake stayed
  "ready" through its own show. *Fix/guard:* model load, gate and show as separate held steps; drop
  readiness at show and emit the change.
- **T-41. Fakes built from imagined data miss the real shapes.** *Seen:* an init returned false on
  every real phone while tests mocked true. *Fix/guard:* fakes from the plugin's source or captured
  payloads; distinct prices nobody would type ("5,49 €").
- **T-42. Fakes at a port hide the adapter beneath it.** *Seen:* with every service test green, the
  analytics adapter could grant ad storage. *Fix/guard:* test adapters against a strict SDK stand-in.
- **T-43. A test-only construction path proves nothing about the shipped one.** *Seen:* a service built
  its own consent gateway whenever a test passed a delay. *Fix/guard:* one factory; a composition test
  of the real app graph.
- **T-44. A required port that silently does nothing hides missing wiring.** *Seen:* an unwired consent
  start looked exactly like "no ad fill". *Fix/guard:* required ports throw, naming the port; null
  objects only where absence is safe and intended (ads, purchases, analytics, cloud).
- **T-45. Process-global hooks leak between tests.** *Seen:* replaced error handlers outlived their
  tests. *Fix/guard:* restore the previous value; unset debug hooks inside the test body.

## 5. Visual and rendering

Depth: `references/visual-design.md`, `references/performance.md`. Every look here was one
project's own; the traps are about method, and each project derives its own identity
(`references/kickoff.md` §7).

- **T-46. A translucent cue over a varied background vanishes; nearly opaque is not the fix.** *Seen:*
  35%-alpha hint dots measured 1.2–1.7:1 on every theme's tiles; cells at 82% failed again over a
  richer background. *Fix/guard:* opaque, in a colour that already carries a contrast rule (≥ 3:1 rim);
  judge composited on the real surface; compute contrast over every theme first.
- **T-47. Themes break each other's cues.** *Seen:* letters drawn on the sky vanished at night; a tint
  that rescued one theme sank another; contrast taken from a gradient's lighter stop passed on paper.
  *Fix/guard:* words sit on a panel or get a night face; re-look every theme after a tint change;
  measure the darker stop, rounded to 8 bits as the display does.
- **T-48. Colour keyed to progress so far recolours everything on each step.** *Seen:* a trail's colour
  divided by cells drawn, so the whole trail shifted every move. *Fix/guard:* index over the total N
  (or by cell, never by path length); render prefixes n and n+1, expect no pixel moved off the end.
- **T-49. A reward drawn under the thing that earned it is invisible.** *Seen:* a full-width trail hid
  half of every tile, the solve reward included. *Fix/guard:* thin the cover first; look at the end.
- **T-50. Lighting and joins that disagree with one key light read as seams.** *Seen:* a band crossed
  the gloss at every corner; a mirrored view flipped the light; a rim over another part read as a cut;
  a part with only an outline read stuck on. *Fix/guard:* one key light (if lit), mirrored back; rims
  clipped outside the part beneath; attach by colour continuity, no root shadow, a thin fillet.
- **T-51. Darkening by multiplication greys warm colours.** *Seen:* cream went grey under RGB multiply;
  shades mixed toward grey read as steel. *Fix/guard:* darken toward a warm hue of the base; sample
  colour per piece (one sample was 25 RGB off along a long seam).
- **T-52. A pose, expression or material cue can say the opposite.** *Seen:* hidden ears made a
  character read as a loaf of bread; raised outer brows read as anger, not worry; a band with a long
  gloss read as an inflatable. *Fix/guard:* check the silhouette; pick the view where the action reads;
  ask a fresh reviewer to name what they see before you tell them.
- **T-53. Geometry in the wrong frame drifts and scales wrongly.** *Seen:* decorations in cell
  coordinates sat off a face not centred on its cell; a band in height units doubled on the large
  hero. *Fix/guard:* place in the visible face's coordinates; assert on the solid part, not the shadow
  margin; judge every element at each size it is drawn.
- **T-54. Painters do not clip, and a paint test proves only that one ran.** *Seen:* a lid swung over a
  heading with every paint test green; a "star" was a 16-gon (inner ratio 0.942) for four phases.
  *Fix/guard:* rasterise on a larger canvas and fail on any pixel outside, sampling motion densely;
  assert looked-up geometry (0.381966).
- **T-55. Tests without the shipped fonts measure the wrong text.** *Seen:* the test font drew every
  glyph as a box; a family without bold drew bold exactly like semibold. *Fix/guard:* load real fonts
  wherever text is measured; two different glyphs must differ; compare weight with weight.
- **T-56. Platform defaults and platform look-alikes make it read as an app.** *Seen:* the most-pressed
  buttons were the only flat things on a glazed board; a lit groove read as a scrollbar; nine corner
  radii coexisted. *Fix/guard:* one surface system for every surface, second ring included; check
  decorations against platform idioms; one token scale per property.
- **T-57. Details verified big vanish at shipped size; a family hides its worst member.** *Seen:* an
  arrowhead checked at 600 px was invisible at 24 px; one generated motif was a torn blob that passed
  every paint test. *Fix/guard:* judge at shipped size beside its neighbours; render all variants on
  one contact sheet (`scripts/contact_sheet.py`) whenever they change.
- **T-58. Randomness at paint time makes pixels unrepeatable.** *Seen:* a constant hash passed visual
  checks while stacking 54 confetti pieces on one point. *Fix/guard:* a seeded index hash, with its
  range and spread asserted; same inputs, same pixels.
- **T-59. The icon and launch screen fail where people meet them.** *Seen:* the head melted into a sky
  of equal luminance at 29 px; the first frame drew the default theme until progress loaded, then cut.
  *Fix/guard:* greyscale squint at the smallest size under every mask; fix the painter, never the
  icon; the launch screen is the first frame's backdrop, checked for returning users in every lighting.
- **T-60. GPUs and renderers differ from the test renderer.** [shader] [Flutter] *Seen:* `smoothstep`
  with e0 ≥ e1 is undefined on Metal and Vulkan but mirrored in tests; blurs redrew on every repaint
  without a raster cache. *Fix/guard:* `1.0 - smoothstep(lo, hi, x)`; sin-free hashes; one layer per
  clock; a draw-call budget test in CI and frame logs from a physical phone.

## 6. Motion and sequencing

Depth: `references/motion-and-feel.md`. The numbers are incidents; each project derives its own feel
(`references/kickoff.md` §7) and tunes it on a device.

- **T-61. An effect keyed to the logical commit runs ahead of its cause.** *Seen:* reactions fired ~35
  ms before the trail reached the item; a cue fired 90–165 ms before its star landed; a reward line
  rose before the gift opened. *Fix/guard:* time effects to visual contact, from the painter's own
  function; write the causal order down first; sound and words never precede the event.
- **T-62. Everything landing at once delivers information and celebrates nothing.** *Seen:* panel,
  stars and "+N" landed in 520 ms, exit buttons legible first; an exit that reversed the arrival
  un-popped the stars. *Fix/guard:* one timeline: achievement, then payment counting up, then exits
  together; an exit never more energetic than the arrival.
- **T-63. A display that jumps before the visual lands says nothing arrived.** *Seen:* the header
  showed the new balance above a "+30" still flying; a coin flew to a counter that did not change.
  *Fix/guard:* persist at once, withhold the shown amount until landing (not under reduce motion or a
  screen reader); animate a transfer only when the destination changes.
- **T-64. Fading something that moves, or two copies of one thing, is a double exposure.** *Seen:* a
  translucent card slid over the board; a page fade over a screen with the same character showed it
  twice. *Fix/guard:* move opaque and in register; fade content, then backdrop; guard every frame
  "character gone, or backdrop opaque"; one fade per change.
- **T-65. Timelines that grow with content or wait for completion feel broken.** *Seen:* a 22-item
  reveal ran 2.96 s; an unbounded stagger never drew item 13; beats waited out whole animations.
  *Fix/guard:* cap the total, test the largest content, delay = `min(i × step, 1 − span)`, overlap.
- **T-66. Input gated, queued or snapped during motion.** *Seen:* snapping teleported an object 200 pt
  and dropped three of four landing cues; an animation that never ran wedged input.
  *Fix/guard:* commit at once, hurry the in-flight motion home (~4×, 70–200 ms), freeze presentation
  facts on the event, settle animations that cannot run.
- **T-67. An overlay accepts taps before it is readable or while it leaves.** *Seen:* a fading panel
  took taps for 1.2 s, skipping levels and doubling ads. *Fix/guard:* ignore input until ~0.3 of the
  arrival; latch "leaving" synchronously on the first accepted tap; test a tap where a button will be.
- **T-68. "Motion off" that is not off.** *Seen:* one mode never got the flag, a new light defaulted to
  animating, the platform reduce-motion setting was unread, frozen particles stayed as dirt.
  *Fix/guard:* no presentation motion scheduled (motion that *is* the task continues:
  `references/motion-and-feel.md` §10); outcomes identical; static outcome signals kept; particles
  removed; test outcomes with the flag off.
- **T-69. Timing arithmetic aliases and mistimes.** *Seen:* a leg cycle per cell hit 30–40 Hz; coins
  42 ms apart buzzed; a rate gate equal to the stagger dropped a third of cues; an ease assumed to be
  1 − (1 − u)³ was a Bézier, so a sound came 20 ms early. *Fix/guard:* cap cadence (6 Hz); aggregate
  events under ~100 ms apart; gates below the interval; sample the framework's real curve.
- **T-70. A reused component carries the previous entity's state.** *Seen:* a tween animated from its
  last shown value on a new level; a completion panel survived onto the next board and swallowed
  taps. *Fix/guard:* key components by entity; reset every cache when inputs change.
- **T-71. A screen frozen after its show reads as dead.** *Seen:* the reward screen sat pixel-identical
  after its 1.9 s show. *Fix/guard:* ambient life at the level the identity sets (stillness only by
  decision), checked with lossless screenshots seconds apart (lossy video alone changes ~10% of
  pixels).

## 7. Sound and haptics

Depth: `references/motion-and-feel.md` §12–§17. Each project derives its own sound identity
(`references/kickoff.md` §7); the incidents below are method, not a palette to copy.

- **T-72. Phone speakers are nearly silent below ~300 Hz; full-band levels mislead.** *Seen:* a +2 dB
  trim made a cue loudest full-band and quietest on a phone. *Fix/guard:* measure through a speaker
  filter (high-passes at 250 and 350 Hz); voice a weak cue with a higher high-pass, not more gain.
- **T-73. Audio guards that check presence or level miss the real faults.** *Seen:* a level guard
  missed a body moved to 150 Hz; "does something start near T" passed with the main strum removed.
  *Fix/guard:* pin the energy share under 250 Hz; per beat, check level and onset count in a window
  that ends before the next beat.
- **T-74. A clean pack can still be "a beep", and a brightening reward hurts.** *Seen:* 21 of 22 cues
  held 90% of energy in one band; reward notes with ~50% of energy in 2–6 kHz were "loud and painful".
  *Fix/guard:* layered cues, one loudness ladder, numeric gates on shipped files; reward steps rise in
  weight while energy above 2 kHz falls (`references/motion-and-feel.md` §14–§15).
- **T-75. Synthesis bugs are invisible until measured.** *Seen:* clicks into a resonator left DC;
  changing one cue's random draws shifted every later cue; integer-sample plucks were out of tune.
  *Fix/guard:* a zero at DC; a seeded stream per cue (a stable hash, never a salted one); fractional
  delays, with a pitch test against the intended note.
- **T-76. Cue scheduling smears or cuts.** *Seen:* buttons went live 0.4 s before a fanfare ended, so
  the expected tap cut its loudest chord; two cues on one frame read as one mush. *Fix/guard:* stop on
  skip only before a "rings out from" time; a stop cancels loading plays; a stronger cue replaces a
  lighter one; skip rapid repeats, never queue them.
- **T-77. Platform audio objects differ.** [iOS] [Android] *Seen:* iOS kept pitch when the rate changed
  and could not decode Ogg; looped MP3s clicked from encoder padding; re-setting a source cold-loaded
  it. *Fix/guard:* pitched files, WAV loops, one player per file, audio context set before any player.
- **T-78. Audio with several reasons to be silent fights itself.** *Seen:* music resumed under a
  full-screen ad; a rate change outside the serialised call chain left a loop silent.
  *Fix/guard:* one sync point reconciles "setting AND foreground AND no suspension", with independent
  suspension reasons; every transport change goes through the serialised chain.
- **T-79. A fallback haptic pattern is a second design to tune.** *Seen:* the success pattern was
  silent below one Android API level; error haptics fired on harmless misses. *Fix/guard:* accept the
  gap, with no fallback pattern; harmless misses get no haptic; the refusal's weight is the feel
  brief's decision (`references/motion-and-feel.md` §12, rule 2).

## 8. Layout, text and accessibility

Depth: `references/ux-and-accessibility.md` (scripts: §Localisation), `references/visual-design.md` §7–§8.

- **T-80. Layouts decided by guesses break at some size.** *Seen:* a width threshold split "Haptics"
  mid-word; one judged on a 440 pt preview never fired on a 390 pt phone for three weeks; a control
  without a reserved slot made content jump. *Fix/guard:* decide by measuring labels; reserve slots
  sized over all variants; nothing reflows under a finger.
- **T-81. Text-scale checks that cannot see the failure.** *Seen:* the shortest copy fitted at 2× while
  the longest hid both buttons; a no-wrap fade and a scale-to-fit box failed silently; a no-break
  space added for looks overflowed. *Fix/guard:* longest strings at the largest scale; pinned actions
  with a scrolling body; compare intrinsic width and the drawn transform; audits overrule polish.
- **T-82. A device matrix that varies only window size is a window matrix.** *Seen:* cards sat under
  the home indicator because tests had no insets. *Fix/guard:* ~6 sizes × text scales up to 3 × real
  safe-area insets × every language, failing on any caught layout error.
- **T-83. A box centres the label's box, not its ink.** *Seen:* labels sat 1.7–3.7 pt high in about 15
  places. *Fix/guard:* nudge by a fraction of font size (≈ 0.18 digits, 0.125 words); whole-pixel
  sizes; guard by weighing ink in the shipped font, with a count floor.
- **T-84. A semantics rectangle is not the touch area.** *Seen:* the mascot was announced as a button
  with no handler; a shrink took money buttons to 36 pt. *Fix/guard:* hit-test inside each node; walk
  the render tree for handlers without a node; measure targets (≥ 44 pt) as the box a finger hits.
- **T-85. Screen-reader users lose the core surface and the outcomes.** *Seen:* the play surface
  exposed zero semantics while chrome was labelled; a paid hint changed only pixels; controls behind
  a dim stayed reachable. *Fix/guard:* announce items and progress; announce outcomes in a live
  region; exclude what sits behind overlays, tested through the live semantics tree.
- **T-86. A refused control must look refused, and busy is not disabled.** *Seen:* a dead button tapped
  at zero balance was pixel-identical before and after; disabled styling dimmed busy dots to nothing.
  *Fix/guard:* refusals answer visibly and are disabled in semantics; a busy control keeps full
  contrast and blocks input separately.
- **T-87. Every control, in every state.** *Seen:* a music toggle with no music; Undo through a win
  overlay unsorted a won board; two controls written as if/else-if lost one. *Fix/guard:* hide
  controls until real; refuse every pressable in every wrong state; test the state matrix.
- **T-88. Off the happy path, the product lies.** *Seen:* a hung loader had no way out; flows held only
  where someone had played. *Fix/guard:* an on-screen way back on every pushed screen; test a
  navigation label by the screen it reaches; sweep by state and sequence, not only screen by screen.
- **T-89. Scripts and directions break text quietly.** *Seen:* letter-spacing broke a joined script; a
  plus sign jumped sides in right-to-left text; a mirrored undo glyph read as "restart".
  *Fix/guard:* whole sentences per language; figures set left-to-right; mirror only directional glyphs.
- **T-90. A source grep cannot find text built at run time.** *Seen:* a localisation pass missed 95
  strings built in getters and helpers. *Fix/guard:* a rendered-tree test that pumps the other language
  and fails on any visible untranslated word.

## 9. State, saves, sync and clocks

Depth: `references/architecture.md` §3–§6.

- **T-91. Overwriting a save that failed to parse, or came from a newer build, destroys progress.**
  *Seen:* a newer build's save looked "corrupt" to an older reader. *Fix/guard:* check the version
  before validating; unparseable → quarantine and start fresh; too new → fresh and never save this
  session; no save before the load finishes.
- **T-92. Save shapes that turn old saves into fresh profiles.** *Seen:* two keys for one profile let a
  crash keep half of it; a new required field would have reset every player. *Fix/guard:* one atomic
  document; new fields optional with defaults; never persist constants.
- **T-93. State-store misuse fails silently.** *Seen:* a mutated list did not notify an equality-
  filtered store; a store updated inside a frame rebuilt the root and broke the frame budget.
  *Fix/guard:* immutable state, always new instances; per-frame values stay in animation objects;
  frame reports go to plain objects, after the frame.
- **T-94. A derived value with no owner shows the wrong number.** *Seen:* a counter read the live
  controller after banking and showed "170" behind "+20"; a once-per-board flag in screen state reset
  on reopen. *Fix/guard:* a rule lives below every consumer and says which source answers when;
  per-item state is saved with the item; latch choices at the user's action.
- **T-95. A fact recorded early, or a save at the wrong moment.** *Seen:* banking time in `pause()`
  wrote the save on every level open. *Fix/guard:* record a fact when it becomes true; persist on the
  real exit paths (lifecycle, Back, completion).
- **T-96. Counters merged by their values lose or double updates.** *Seen:* max handed back spent items,
  sum doubled shared ones, a three-way merge lost updates under last-writer-wins. *Fix/guard:*
  per-install grow-only ledgers in the same document; every merged field a function of the union.
- **T-97. A merge without algebra never converges.** *Seen:* a commutative, non-associative join made
  two simulated phones rewrite each other for ever (pairwise tests passed); a fresh install's empty
  state wiped another device's streak. *Fix/guard:* test the semilattice laws with a randomised
  multi-replica model and skewed clocks; "nothing to decide" is not a decision.
- **T-98. Sync feedback loops.** *Seen:* a clock clamp saved from a merge looped writes between phones;
  each merge commit scheduled another sync. *Fix/guard:* clamp where the bookkeeping runs, never in a
  merge; a mirror ignores its own writes and re-syncs only if local data moved.
- **T-99. Clocks, days, calendars and seeds are exploitable inputs.** *Seen:* a local-midnight day
  count failed only across daylight-saving; a stopwatch stopped while the phone slept; "fresh" modes
  served seed 1 for ever; a calendar passed four known dates but broke on 98 days. *Fix/guard:* days
  from local Y/M/D asked of UTC, tested in several `TZ=` zones; wall clock for gaps; sample the clock
  once per transaction; seed from real inputs; date code checked every day against another library.

## 10. Async, timeouts and lifecycle

Depth: `references/architecture.md` §7–§8.

- **T-100. A platform call can simply never answer.** *Seen:* a channel without a handler never
  replied; a crash-reporting init never answered on an emulator; an SDK flow without a dismiss
  callback could freeze "Next". *Fix/guard:* bound every platform await; own watchdogs on SDK flows;
  never-throw ports; no unbounded wait before the first frame.
- **T-101. A timeout neither cancels the call nor helps a read nobody awaits.** *Seen:* a late answer
  left a loop playing that nothing could stop; a `dispose()` awaiting loads hung for ever.
  *Fix/guard:* set state before awaiting; let loads dispose themselves; don't bound fire-and-forget
  reads (a bound only discards a slow true answer); order them instead (T-103).
- **T-102. A timeout whose fallback is the risky side undoes the rule it serves.** *Seen:* ads waited
  20 s for an age answer, then proceeded as adult, while the age sheet could take 2 min.
  *Fix/guard:* bound each underlying call and let the dependent wait, or fall back to the safe side.
- **T-103. A stale read overwrites a newer one.** *Seen:* a slow consent read answered after a newer
  one. *Fix/guard:* number overlapping reads and apply only the latest; a bound does not fix order.
- **T-104. Every await between check and take is a gap.** *Seen:* two presenters awaiting one "safe
  moment" both took it; a tap pushed a route in the frame a sheet was presenting. *Fix/guard:* check
  and claim in one synchronous step; re-check after the end of the frame.
- **T-105. A gate checked before a network-bound call is stale when the result appears.** *Seen:* a
  consent form loaded for 0.5–3 s inside one native call; the SDK retried a failed flow on its own
  timer and showed it mid-task. *Fix/guard:* hold the moment until the call ends (bounded); gate at show.
- **T-106. Timers count wall time, background included.** *Seen:* a hold fired overdue on return from
  the background. *Fix/guard:* frame tickers, or cancel timers on backgrounding and restart on return.
- **T-107. Lifecycle events are not what they look like.** *Seen:* a full-screen video backgrounded
  the Android app, so the level clock counted it; the iOS share sheet pushed no route and the app
  stayed resumed. *Fix/guard:* an ad's background is not leaving; the share press blocks prompts too.
- **T-108. Callbacks outlive their context or re-enter themselves.** *Seen:* a timer between a tap and
  the rebuild used stale state; a listener that changed what it listened to granted a reward
  recursively on one level in eight. *Fix/guard:* live state in callbacks; cancellable timers; a guard.

## 11. Content generation

Depth: `references/domain-games.md`, `references/architecture.md` §10.

- **T-109. Content valid by every test can still be bad to a human.** *Seen:* 2,027 proven-unique
  levels included one whose numbers formed a straight row "like a barcode"; generated answers
  included a misspelling and a person's name. *Fix/guard:* read the first N items as a user meets
  them, plus the boundary and what filters removed; each finding becomes a rule in every verifier.
- **T-110. Every generator move set has structural biases.** *Seen:* path moves never changed the
  parity of the head, so item 1 always sat on one checkerboard colour; midpoint insertion clumped
  numbers. *Fix/guard:* inspect distributions by eye; randomise the bias away at the source.
- **T-111. Pruning and deduplication done on the surface.** *Seen:* most walls did nothing, because
  "is this wall needed?" is not monotone; distinct puzzles shared one solution route.
  *Fix/guard:* prune repeatedly to a fixed point; deduplicate by the underlying solution too.
- **T-112. Difficulty from intuition or class ranks is wrong.** *Seen:* levels 1–17 were never lost; a
  "hard" label sat on a level a random walk wins; broad classes overlapped. *Fix/guard:* a kept
  instrument (dead-end rate over 300–500 random playouts); compare measured ranges, never ranks.
- **T-113. Artefacts must be reproducible and measured at the end.** *Seen:* output depended on worker
  completion order and a salted string hash; a metric rounded mid-pipeline shipped wrong.
  *Fix/guard:* slot order, stable hashes, canonical tie-breaks; recompute metrics from the final file.
- **T-114. Solvers need bounded resources and their own thread.** *Seen:* a memo hit 136 MB on the
  largest board; eight busy workers starved the test runner so its timeout never fired.
  *Fix/guard:* a memory-bounding rule plus a step cap; never on the UI thread; ≤ 4 workers per test
  file; distinguish "proved impossible" from "gave up".
- **T-115. Twin implementations drift, and answers alone hide weaker pruning.** *Seen:* a
  second-language twin proved configurations the app never dealt. *Fix/guard:* re-prove the shipped
  file in the app's language in CI; compare node counts; the solver learns a mechanic first.

## 12. Platform and native projects

Depth: `references/release-and-store.md` §1 and §8, `references/architecture.md` §11,
`references/stack-flutter.md` §12.

> **Dated facts (as of 2026-10 — re-verify before relying):** iOS 27 refused to launch apps built
> with its SDK that lacked the scene-based lifecycle; Android 16 at target API 36 ignored a fixed
> orientation on screens ≥ 600 dp unless the app declared the game category; an iPad-capable build
> had to support all four orientations, so portrait-only apps shipped iPhone-only; Android Auto
> Backup silently backed up nothing over 25 MB.

- **T-116. The platform scaffolder run over the repo overwrites decisions.** *Seen:* a bare project
  create rewrote the entry file, manifest, lint config and ignore file; 126 generated files were
  committed. *Fix/guard:* scaffold in a temp dir, copy out platform folders, checksum hand-written files.
- **T-117. A patch that matched nothing looks exactly like one that worked.** *Seen:* a stock icon, a
  wrong-language label and a debug-signed bundle shipped; a `sed` on the old name stopped matching
  after a rename. *Fix/guard:* edit by attribute, not old value; a check after each edit, and every
  check again on the final tree.
- **T-118. Text greps ignore inheritance and membership.** *Seen:* device family was inherited from
  project level; a privacy manifest was in the project but not in the bundle. *Fix/guard:* query the
  effective value per configuration; check build-phase membership; open the built app.
- **T-119. Inputs are data: validate them before deleting anything, and never execute them.** *Seen:*
  a bad input found after `rm -rf` left a stock half-patched template; a trailing CR from a sourced
  env file made the ad SDK throw at launch. *Fix/guard:* validate first (a test asserts the order);
  unknown or half inputs fail; parse `KEY=value` line by line; unported steps fail loudly.
- **T-120. What lives only in generated folders is deleted on regeneration.** *Seen:* the signing
  config lived in the regenerated folder, so releases silently fell back to debug signing.
  *Fix/guard:* keep it outside, write it in each run, verify the certificate; two installs identical.
- **T-121. Generation steps that are not reproducible.** [iOS] [Flutter] *Seen:* a config-only iOS
  build ran a pod install that wrote random object ids; the scaffold's temp path leaked into
  generated config. *Fix/guard:* avoid the step that adds randomness; delete leaked files, re-fetch,
  assert paths point at the checkout.
- **T-122. Defaults nobody chose become decisions.** *Seen:* an iPhone-and-iPad default produced iPad
  screenshots, then an orientation rejection. *Fix/guard:* record each chosen value (device family,
  orientation, category) in DECISIONS and verify the effective one.
- **T-123. Platform theme resources outrank each other unexpectedly.** [Android] [iOS] *Seen:* a night
  styles file outranked the API-31 styles and dropped the splash; iOS cached a launch screen until
  reinstall. *Fix/guard:* night resources only via named colours and booleans; reinstall to judge.
- **T-124. Fragile external pieces.** *Seen:* the only plugin for a needed signal was a 33-download
  solo fork missing events; an IDE scheme edit could not be scripted idempotently. *Fix/guard:* a
  small in-repo plugin (~140 lines) behind a port; unscriptable edits become owner-list steps.

## 13. Release and store

Depth: `references/release-and-store.md`.

> **Dated facts (as of 2026-10 — re-verify before relying):** recent Android Gradle Plugin versions
> enabled full-mode shrinking for release by default; stores accepted stale or sample-id builds and
> rejected some only hours after upload ("Invalid Binary"); App Store guideline 2.3.1(a) covered
> features described but not reachable; App Review required an in-app privacy-policy link.

- **T-125. Built is not runs.** *Seen:* in a word game the release shrinker stripped a constructor
  loaded by reflection; every release build died at start and the store rejected it as "keeps
  stopping". A sorting game hit the same fault with 605 tests green; its own launch gate caught it
  before upload. *Fix/guard:* install the release artefact fresh, cold-start it, drive the core
  flows; check statically that every class built by name keeps its constructor.
- **T-126. Liveness signals lie.** *Seen:* the process id survived a crash (Android kept it warm); the
  launch screen matched the home backdrop, so a stuck build looked fine. *Fix/guard:* prove the app's
  own code ran via an accessibility node only it publishes, plus the top activity and crash buffer.
- **T-127. A release with crash reporting prints no findable error line.** *Seen:* greps for the
  engine's "Unhandled Exception" never matched. *Fix/guard:* the handlers print a fixed marker; the
  gate greps every log shape, with a selftest feeding it each one.
- **T-128. The artefact you test may not be the one you upload.** *Seen:* an 11-hour-old bundle was
  nearly uploaded after five commits; a stale apk sat beside a fresh bundle. *Fix/guard:* fail if older
  than the code; test the uploading bundle; read the version back off the device; every override is
  a named flag that prints itself.
- **T-129. Sample ids ship when the real ones go missing.** *Seen:* a gitignored ids file was absent on
  the build machine; "are sample ids absent?" fails when a library compiles test ids into every build.
  *Fix/guard:* invert it: require every production id present in the binary.
- **T-130. A store claim not derived from code is a lie waiting to be found.** *Seen:* an earlier app
  claimed "nothing leaves your phone" while running analytics. *Fix/guard:* a claim table, each line
  anchored to the code fact that makes it true, checked mechanically.
- **T-131. Two banned-word lists drift.** *Seen:* the screenshot test's shorter list let through words
  the copy checker knew. *Fix/guard:* one list (competitor names, claims you cannot keep) over every
  text a store or player sees, captions included.
- **T-132. A dormant feature or a capped promise is a review problem.** *Seen:* a daily mode was
  advertised with a screenshot before its start date; "earn a reward every 7 days" was false at the
  cap. *Fix/guard:* date every line naming a not-yet-live feature, explain it in the review note,
  drop its screenshot; state caps in the claim.
- **T-133. Reviewers meet the app differently from you.** *Seen:* a reviewer never reached a tracking
  prompt shown after the fourth puzzle; one used an iPad in iPhone mode; six investigators agreed on a
  rejection's cause and were wrong. *Fix/guard:* a review-note constant checked against the source;
  launch on the reviewer's device class; reproduce a rejection before believing any explanation.
- **T-134. Store media made the easy way misleads or breaks.** *Seen:* the solve's goal frame was the
  worst still; a debug build stalled its first heavy animation on camera; an encoder wrote "256 kbps"
  silence at ~2 kbps. *Fix/guard:* drive the real app; pick stills from a filmstrip; warm up off
  camera; null ads and cloud in recordings; check bit rate and content in the output file.
- **T-135. Hand-typed versions and dates drift silently.** *Seen:* a review prompt keyed to a typed
  version would never ask again; a release script encoded the day it was written. *Fix/guard:* read
  versions from the manifest, pinned in a test; nothing branches on whether a prompt appeared.
- **T-135a. A slow pre-check before a one-shot prompt loses it.** *Seen:* an availability check before
  the store review request made a slow platform-services call; it answered after the turn was saved,
  and the only prompt never appeared. *Fix/guard:* request directly at the settled moment.

## 14. Monetization and privacy

Depth: `references/monetization-and-privacy.md`. Every platform rule here is dated; re-verify.

> **Dated facts (as of 2026-10 — re-verify before relying):** a Play billing plugin answered a
> cancelled flow with a purchase whose product id was empty, and its restore stamped PENDING
> purchases "restored"; the StoreKit plugin asserted auto-consume true for consumables and its
> completion call could wait for ever; Screen Time made "can make payments" false for good; a privacy
> manifest declaring tracking with no domains was rejected as Invalid Binary, and listed tracking
> domains were blocked for users who declined; an iOS 27.0/27.1 bug returned "not determined"
> without showing the prompt; console-driven prompts depended on a console checkbox (rejection under
> 5.1.2(i) when unticked); privacy labels answered "linked" and "tracking" once per data type.

- **T-136. An irreversible external event recorded after its await is lost on a kill.** *Seen:* an
  impression written after `await show()` vanished when the player killed the app under the ad, so
  the next ad came a level early. *Fix/guard:* a provisional record at hand-off (awaited, bounded),
  settled or withdrawn by compare-and-set; prove it with a held show and a fresh container.
- **T-137. A purchase finished before its grant is saved can be lost.** *Seen:* a "saved" answer
  after a failed write finished the transaction with the grant only in memory. *Fix/guard:* persist the
  grant (the write's answer, not its call) before finishing; remember failed writes; the saved
  purchase id stops double counting on redelivery.
- **T-138. An SDK flips "ready" false during its own show.** *Seen:* an offer card following live
  readiness slid away saying "no video is ready" with the reward pending. *Fix/guard:* freeze what an
  offer shows from the moment the user answers it.
- **T-139. A rewarded video lost on a pop breaks trust.** *Seen:* a fully watched ad paid nothing when
  its screen was popped mid-video, and skipped the cooldown. *Fix/guard:* pay on the reward callback;
  set an in-flight flag before the await; grant and record before any "still mounted" check.
- **T-140. Pending full-screen content must block leaving through real state.** *Seen:* a flag set
  outside the framework's state never reached the input shield, and system Back ignores shields; the
  ad appeared over home. *Fix/guard:* a can't-leave state in the framework; check "on top" at show.
- **T-141. A consent explainer recorded early, or awaited for ever.** *Seen:* its date was recorded at
  the push, so a player who killed the app met the bare system alert next launch; the SDK awaited it
  with no timeout while navigation could remove its route. *Fix/guard:* record it when answered; it
  completes on Continue, on route removal or on a long timeout; "not determined" means ask later.
- **T-142. Store plugins invent shapes your code never expects.** *Seen:* a cancel arrived as a
  purchase with an empty id; PENDING purchases came back "restored"; reading the store object
  connected at construction. *Fix/guard:* read each platform implementation; answer every buy in
  flight; never grant or acknowledge pending; never await completion; connect lazily.
- **T-143. Platform declarations have consequences you did not intend.** *Seen:* listing the ad
  network's domains as tracking domains would have blocked ads for every decliner. *Fix/guard:* read
  each declaration's effect; guard the literal reviewed shapes in the built artefact; prefer
  client-driven prompts the build can verify.
- **T-144. Labels and legal forms are answered once, and wrongly by accident.** *Seen:* a type declared
  "linked" for ads could not be added as "not linked" for analytics; a resized window nearly answered
  "collects no data" for an ad-funded app. *Fix/guard:* a union table, one final answer per data type;
  read back every selection before the commit button.
- **T-145. Telemetry measures the wrong thing.** *Seen:* the consent "changed" callback also fired at
  the end of the first flow; a replay was logged as a first solve time. *Fix/guard:* ignore the first
  callback as a change; carry first/replay on events; record opportunities with outcomes.
- **T-146. Policy wording scoped loosely forbids or promises the wrong thing.** *Seen:* "never
  mid-level" for interstitials forbade a player-chosen rewarded video; "removes all ads" drew
  complaints while rewarded stayed. *Fix/guard:* scope rules by ad type; "Remove Ads" says exactly what
  it removes; ban each claim false for this product (there: "no ads", "free").
- **T-147. A charming character can make an ad-funded app look child-directed.** *Seen:* a cute
  animated mascot was flagged as a child-directed factor; adding a child age group to answer a flag
  would have pulled in family-program rules. *Fix/guard:* decide the audience as a recorded decision
  (that project chose 18+ and adult-coded its listing); never time out an age check to "adult" (T-102).

## 15. Tooling and shell

Depth: `references/verification.md` §12.

- **T-148. zsh does not word-split `$VAR`.** [shell] *Seen:* a `for` loop over a variable wrote garbage
  into a source file, twice. *Fix/guard:* such loops run in bash scripts; promote to a template.
- **T-149. Bulk edits and blanket adds reach files you did not mean.** *Seen:* formatting a folder
  rewrote other lanes' files; a global `sed` rewrote a gitignored cache; a blanket `git add` committed
  eight files the first test run had generated. *Fix/guard:* format and stage an explicit file list;
  scope find-and-replace to source folders; `git status --short` in the baseline.
- **T-150. Shell exit codes lie.** [shell] *Seen:* `cmd | grep -q` under `pipefail` failed on a real
  artefact; `set -e` ended a script silently when `pidof` found nothing. *Fix/guard:* grep a variable
  (`<<< "$var"`); a load-bearing `|| true`.
- **T-151. Old shells parse modern scripts differently.** [shell] *Seen:* macOS bash 3.2 misparsed a
  heredoc apostrophe inside `$( )` and read `$NAME»` as unbound. *Fix/guard:* brace `${NAME}`; test on
  the shipped shell.
- **T-152. String and path operations widen silently.** *Seen:* `rsync --exclude ios` excluded every
  folder named ios; an empty Python slice fed `replace('', x)`, which mangled a whole file.
  *Fix/guard:* anchor patterns (`/ios`); assert slices are non-empty before use.
- **T-153. Loose equality across types passes wrong values.** *Seen:* Python's `False == 0` passed a
  plist comparison. *Fix/guard:* check types before comparing.
- **T-154. A scripted edit or a cache that silently does nothing.** *Seen:* a sabotage `sed` with the
  wrong indentation matched nothing, so the guard "passed"; a truncated download gave plausible,
  worthless output. *Fix/guard:* assert the target exists once before editing; size-check caches.
- **T-155. Version-control shortcuts during probes destroy work.** *Seen:* `git checkout -- file` to
  drop a probe discarded an uncommitted chapter, twice; worktree agents started from the default
  branch. *Fix/guard:* commit first or probe in a copy; give worktree agents the exact base commit.
- **T-156. Shared machines carry other sessions' state.** *Seen:* parallel lanes collided in one
  scratch folder; a killed run left the test host spinning; a booted simulator belonged to another
  session. *Fix/guard:* lane-unique names; kill strays by path; check what is in front; wait on locks.
- **T-157. Simulators, emulators and test tools inject their own behaviour.** [iOS] [Android] *Seen:*
  the tool lifted the last touch without a final move; launches reinstalled into a fresh container; a
